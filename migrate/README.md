# Z-English: Google Sheets → Supabase Migration

## Overview

This directory contains the migration script that moves all data from the
original Google Sheets backend (`backend_Code.gs.local`) to the Supabase
database used by the Vercel serverless backend (`api/backend.js`).

## Prerequisites

1. **Node.js 18+** installed
2. **Supabase credentials** (from your Vercel project or Supabase dashboard)
3. **Google Sheets data exported as CSV** (one file per sheet tab)

## Step 1: Export Google Sheets Data as CSV

In Google Sheets, for each tab (sheet), export as CSV:

1. Click on the sheet tab you want to export
2. Go to **File → Download → CSV (.csv)**
3. Save each file as `sheets/<sheet-name>.csv`

## Step 2: Set Environment Variables

```bash
export SUPABASE_URL="https://your-project-ref.supabase.co"
export SUPABASE_SERVICE_ROLE_KEY="your-service-role-key"
```

Or create a `.env` file in the project root:
```
SUPABASE_URL=https://your-project-ref.supabase.co
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
```

## Step 3: Run the Migration

```bash
node migrate/gs-to-supabase.js
```

The script will:
1. Read each CSV file from `sheets/`
2. Map Google Sheets columns to Supabase table columns
3. Handle chunked JSON columns (LessonContent, TempSessions, PublicSessions)
4. Insert data in batches of 50
5. Detect and remove placeholder/demo posts
6. Print a summary of inserted/skipped/errored records

## Schema Differences (Supabase has more header slots)

| Supabase Table | Extra Columns | How Handled |
|---|---|---|
| `users` | `provider`, `created_at` | `provider` defaults to `'password'`; `created_at` auto-fills |
| `unlocked_levels` | `id` (bigint identity) | Auto-generated by Supabase |
| `lesson_access` | `id`, `created_at` | Auto-generated by Supabase |
| `tutor_sessions` | `id` | Auto-generated by Supabase |
| `likes` | `id`, `created_at` | Auto-generated by Supabase |
| `comments` | `id` | Auto-generated by Supabase |
| `categories` | `position` (vs GS `order`) | Mapped from GS `order` column |
| `custom_sessions` | `created_at` | Auto-fills |
| `lesson_content` | `updated_at` | Auto-fills |
| `sessions` | `updated_at` | Auto-fills |
| `test_submissions` | `id` | Auto-generated by Supabase |
| `payment_links` | `created_at` | Auto-fills |
| `contact_messages` | `id`, `created_at` | Auto-fills |
| `media` | `id`, `url`, `mime_type`, `filename`, `created_at` | Not migrated from GS (Drive-based) |

## Placeholder Posts

The migration script automatically detects and removes placeholder/demo posts
based on content patterns like "hello", "welcome", "test post", "sample post",
"demo", "placeholder", "lorem ipsum", "delete me", "dummy", etc.

To manually remove remaining placeholder posts after migration, run this in
the Supabase SQL Editor:

```sql
DELETE FROM posts
WHERE content ILIKE '%hello%'
   OR content ILIKE '%welcome%'
   OR content ILIKE '%test%'
   OR content ILIKE '%demo%'
   OR content ILIKE '%placeholder%'
   OR content ILIKE '%sample%'
   OR content ILIKE '%lorem%';
```
